## 项目简介

sipkit 为 MoonBit 生态补上 SIP（RFC 3261）缺失的信令层：对 mooncakes.io 全部 3,243 个模块与 2026 年新建的 1,805 个 MoonBit 仓库检索，SIP 本体命中为 0，而 WebRTC 媒体栈与 SDP 已有人做——"描述会话"的层存在，"建立会话"的层缺失。sipkit 提供**字节级**的 SIP 消息解析、可逐字节还原的重新序列化、以及带字节偏移的结构诊断（语法层 / 诊断层分离，与 RFC 4475 对语料的划分一致），采用 sans-IO 设计：库不碰 socket，输入输出全部由调用方提供。正确性不以自我声明度量，而以 IETF 官方测试集 RFC 4475 全部 49 条报文为外部证据，在**判定级、字段级、鲁棒性级**三个层次上验证：45 条判定断言全部一致，RFC 原文明确给出的字段期望（如"the user part is 'user;par=u@example.net'"）逐字断言，4,000+ 敌意输入零 panic。面向需要在 MoonBit 中收发或分析 SIP 报文的网关 / SBC 开发者、话单与信令取证工具、协议教学与对照基准的作者。

## 核心功能范围

- 提供 RFC 3261 消息层解析：Request-Line / Status-Line、头块（含 CRLF 折行与 HCOLON 空白规则）、按 `Content-Length` 的 body 分帧；
- 提供 SIP URI 解析（RFC 3261 §19.1）：userinfo / password、IPv4 与括号 IPv6、port、`;` 参数、`?` URI headers，百分号转义严格单次解码（`%41`→`A`，`%2541`→`%41`，不递归）；
- 提供 name-addr / addr-spec / absoluteURI 地址模型：quoted-string 与 token 显示名、头参数、逗号分隔列表（不切开引号内逗号）；
- 支持 RFC 3261 Table 2 单字母紧凑头名（`i` `l` `v` `t` `f` `m` `c` `s` `k` `e`）双向识别；
- 提供逐字节还原的重新序列化 `to_bytes`：对任何 CRLF 分帧的输入原样返回，`trailing` 暴露同一数据报中的后续字节而不重新粘回，抵御请求走私面；
- 提供两层判定入口 `analyze`：永不抛异常，输出 `well-formed` / `syntax-rejected` / `semantic-rejected` 三值判定与字节偏移；
- 提供 18 个缺陷码的诊断层，error / warning 两档严重级（仅 error 改变判定），每个缺陷码引用其来源的 RFC 4475 用例；
- 保持**零依赖**（core 之外无 import）与库内零 `unwrap`/`panic`/`abort`，注释嵌套以深度计数（上限 16）替代递归以防栈耗尽；
- 提供一致性证据工具链：RFC 4475 提取器实现 RFC §2 的 `<allOneLine>` / `<hex>` / `<repeat>` 表示法并处理跨页，49 条报文可从 rfc-editor.org 重新生成并逐字节比对；
- 提供字段级一致性测试：RFC 正文明确给出的字段期望（§3.1.1.9 的 `user;par=u@example.net`、§3.1.1.5 的两个 Contact、§3.1.1.4 的 `%00` 不截断 AOR、§3.3.12 的 contact-param 归属）逐字断言；
- 提供鲁棒性测试：随机字节、结构字节、截断、单字节变异、拼接注入五类确定性生成器，4,000+ 输入零 panic；
- 提供不少于 79 个 MoonBit 测试并保持全后端回归通过（wasm / wasm-gc / js / native），库内行覆盖率约 97%（50 / 1,698 可执行行），112 个公开函数 100% 带文档注释；
- 提供 GitHub Actions CI 六项检查：四后端 check / test / build、语料从 rfc-editor.org 重提取逐字节比对、LICENSE 与 NOTICE 合规校验；
- 提供三个可运行示例（`moon run examples/parse_dump | diagnose | uri`），README 附真实运行输出，覆盖解析还原、三种判定与 URI 边界情形；
- 记录规范冲突的决策依据：RFC 4475 intmeth 报文与 RFC 3261 ABNF 在 user 部分是否允许 `:` 上存在冲突，实现选择可辩护的一侧并写入测试注释与限制清单。
